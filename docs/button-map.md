## 實測證據

| 按鈕 | L0 實測 | L1 實測 |
|---|---|---|
| MIC | 沒有事件 | Up（0x52） |
| APPR | Enter（0x28） | Down（0x51） |
| REJ | Esc（0x29） | Left（0x50） |
| OAI | Tab（0x2B）＋ LAlt（0xE2） | Right（0x4F） |
| 左側層切換按鍵 | 沒有事件 | 沒有事件 |

- 四顆按鈕由上到下就是位置 0–3。L1 的 Up／Down／Left／Right 順序和設定完全一致，可以確認這一點。
- 背面切到 L1 之後，不用按住任何鍵，方向鍵就生效。所以背面切換應該是一直按住位置 5（`Momentary Layer 1`）。這是推論。
- **位置 4（`Momentary Layer 2`）沒有接到任何實體按鍵**：2026-10-14 暫時把 L0 位置 4 改成 F13（未存檔），依序按左側按鍵、撥背面開關、按四顆鍵帽，都沒有出現 F13；測完已改回並讀回確認與快照相同（`snapshots/2026-10-14-side-button-test.txt`）。因此依目前配置，**L2 多媒體層無法用任何實體按鍵進入**。
- 韌體每層有 7 個位置，但實體配置只定義 6 個；Studio 依實體配置讀寫，第 7 個位置看不到也改不了（zmk `keymap.c` `zmk_keymap_get_layer_binding_at_idx`）。左側按鍵應是這個位置，要重新綁定只能改韌體（賣家的 zmk-config）。
- 按住左側按鍵時：L0 按鍵照常送出；背面在 L1 時再按 APPR 則完全沒有輸出。這個差異的原因未明。

## 麥克風（vibe_ptt）

2026-10-13 訂閱賣家自訂服務 `1ACCAC91-73C2-41CA-AF88-7C02247CA900` 的通知後實測（`snapshots/2026-10-13-vendor-notify-mic.txt`）：

| 特徵值 | 觀察 | 解讀 |
|---|---|---|
| `…A903` | 按下 MIC 送 `01`，放開後送 `00` | 收音開始／結束 |
| `…A902` | 收音期間每 20 ms 一筆 80 B，約 3,950 B/s | 聲音資料串流，格式見下方「聲音格式」 |
| `…A909` | 每次 HID 按鍵按下／放開各送 8 B，例如 `04002B01…` | 按鍵鏡像：位元組 0 = 修飾鍵（`04` = LAlt）、位元組 2 = HID usage、位元組 3 = `01` 按下／`00` 放開；切層鍵本身不送 |
| `…A905` | 每秒一筆 3 B，例如 `410001` | 第 1 個位元組是電量百分比：2026-10-13 23:56 標準電池服務 `2A19` 讀到 `0x41`（65%），同時刻 `A905` 也是 `0x41`；後 2 個位元組意義未知 |
| `…A908` | 沒有資料 | 未知 |

### 聲音格式（未解開，2026-10-13 暫停研究）

**已確認**：按住 MIC 時，`…A902` 每 20 ms 送一個 80 B 封包（約 32 kbps）；`…A903` 回報開始／結束。

**已排除**：

| 假設 | 依據 |
|---|---|
| 8-bit PCM／µ-law／A-law | 相鄰取樣相關接近 0 |
| 每個封包是一個 Opus 封包（32 kbps、20 ms 剛好 80 B） | 包成 Ogg Opus 交給 ffmpeg／libopus，224 個封包中 125 個 `Error parsing the packet header` |
| IMA ADPCM 先高 4 位 | 相鄰取樣相關 0.08～0.13，接近雜訊 |

**未能確認**：IMA ADPCM 先低 4 位（逐封包重設或連續）。說話錄音的相鄰取樣相關約 0.65 像語音，但使用者聽不出聲音；受控測試（Mac 喇叭播 3 秒 1 kHz 音調，`snapshots` 外的錄音檔 `vibestick-20261013-233719.adpcm`）解碼後整段約 −60 dBFS，看不到音調，原始位元組也沒有 1 kHz 應有的 4／8 位元組週期。

**其他線索**：每個封包第 1 個位元組隨內容變化（說話時多為 `0x79`～`0x7D`，音調時多為 `0xF1`～`0xF5`），可能是編碼參數；也可能資料經過加密或使用未知的編碼器。

**建議下一步**：取得賣家的配套 App 或協定說明（最可靠）；或在有更多錄音樣本時再分析。UI 的「存成 WAV」為實驗性功能，原始 `.adpcm` 檔可供日後分析（`probe/analyze_adpcm.py`、`probe/wrap_ogg_opus.py`）。

- macOS 沒有把這台鍵盤列為音訊裝置，鍵盤 HID 報告也沒有音訊，所以**不能當成一般麥克風直接用**。聲音只從自訂服務傳出，需要自己的程式接收與解碼。
- `…A901`、`…A906`、`…A907` 只能寫入，用途未知，從未寫入。
